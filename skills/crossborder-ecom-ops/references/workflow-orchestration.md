# 端到端编排：阶段边界与交接字段

七个阶段可以单独调用，也可以按 `规则 → 数据 → 选品 → 素材 → 投流 → PO → 复盘` 串联。线下门店的手写单据走 ②B 台账支线，与主链路并行、互不阻塞。串联时每个节点交付「上表 + 信封 + 待办」，下一个节点只接受结构化输入，不接受口头结论。

## 串联顺序与依赖

```text
① 规则费率 ──┐
             ├─▶ ③ 选品测算 ──┬─▶ ④ 视频素材 ──▶ ⑤ 广告投放 ──▶ ⑦ ROI 复盘 ──┐
② 表格整理 ──┘                └─▶ ⑥ PO 单 ─────────────────────────────────────┘
                    ▲                                                            │
                    └──────────────── 复盘结论回流，修正参数与素材方向 ◀──────────┘

②B 手写单据台账（并行支线）：拍照 → 识别 → 简写标准化 → 自动算账 → 采购/销售日结 → 凭证回链
      └─▶ 标准品名台账直接供 ③ 算毛利、⑦ 做周期复盘、⑥ 转补货需求
```

- **① 与 ② 可以并行**：规则采集和表格清洗互不依赖，谁先完成都不影响对方。
- **③ 依赖 ① 的费率表和 ② 的干净商品表**：费率缺失时选题测算只能给区间，不能给确定结论。
- **④ 与 ⑥ 可以并行**：素材生产和采购下单互不阻塞，但都依赖 ③ 定下的 SKU 与价格。
- **⑤ 依赖 ④ 的素材编号**：素材编号（`{SKU}_{站点}_{钩子}_{比例}_{时长}_v{n}`）必须一致，否则复盘时拉不齐素材维度的数据。
- **⑦ 依赖 ⑤ 的命名规范**：活动命名不规范，复盘就无法按维度聚合。

## 阶段交接字段

上游交给下游的最小字段集，缺字段时下游先输出待补清单（`status: blocked`），不要用经验值补。

| 交接 | 必须传递的字段 | 从哪个产物取 |
|---|---|---|
| ① → ③ | `platform`、`site`、`category`、`commission_rate`、`payment_rate`、`currency`、`source`、`effective_date` | `fee.json` / 费率表 |
| ② → ③/⑦ | 归一后的字段名映射、单位声明、去重主键、被隔离行及原因 | `clean.json` 的清洗台账 |
| ②B → ③/⑥/⑦ | `date`、`direction`（采购/销售）、`item_std`（标准品名）、`qty`、`unit_price`、`amount_written`、`photo_path`、校验状态与差异行清单 | `ledger.json` 的 `daily` / `calc_check` / `alias` |
| ③ → ④ | `sku`、`site`、`product_name`、`category`、`audience`、`selling_points`、`proof`、`offer`、`price`、`currency` | `selection.md` / 选品结果 |
| ③ → ⑥ | `sku`、`qty`、`unit_price`、`currency`、`lead_time`、`moq`、`trade_term` | 选品结果 + 供应商报价 |
| ④ → ⑤ | 素材编号、钩子编码、比例、时长、目标语种、前三秒判定结果 | `brief.json` 的 `assets` |
| ⑤ → ⑦ | `campaign` / `ad_group` / `ad` 命名、保本 ROAS、止损阈值、观察窗定义 | 投放结构表 + 阈值表 |
| ⑦ → ③/④ | 亏损与低效分组、归因结论、下周动作、需要复测的素材方向 | `review.md` / `review.json` |

## 人机协作的三个卡点

串联链路上只有三处必须停下来等人，其余交给 AI 连续执行：

1. **资金卡点**：PO 下单、付款、超阈值预算调整、改价——AI 只出方案与校验结果。
2. **合规卡点**：素材命中禁用词、认证与标签缺失、类目准入不明——AI 只出判定与整改建议。
3. **风险结论卡点**：正毛利被判亏损、净利为负仍要上架、环比异常但数据存疑——AI 标记，人工终审。

卡点的判定规则固定写进 `flags`，不要靠临时判断；卡点之外的判断 AI 直接执行并留痕，减少人工在低风险节点上的介入。

## 单阶段与全链路

- **单阶段**：用户只问一个环节时，直接调用对应阶段技能，不要为了「完整」把七个阶段都跑一遍。
- **全链路**：用户要端到端结果时，按串联顺序逐段输出信封，每段完成后先汇报该段结论与 `flags`，再进入下一段；`status: blocked` 的阶段先补齐输入，不要跳过。
- **中断恢复**：链路中断后，从最后一个 `status: ok` 的阶段继续，已产出的文件不重跑，避免同一批数据出现两个版本。

## 团队口径沉淀

每跑完一轮，把稳定的部分固化成文件，下一轮直接复用而不是重新解释：

- 判定规则与阈值 → 写进对应阶段技能的 `references/`。
- 成功的作业模板 → 按 `prompt-contract.md` 封装成可复用 Skill。
- 出过问题的场景 → 记进 Badcase 清单，标明触发条件与修法。
