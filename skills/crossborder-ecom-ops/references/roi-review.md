# 阶段 6：ROI 数据复盘

目标：把投放与销售明细算成可决策的结论——哪些组在赚钱、赚在哪、亏在哪、下周动什么。复盘的价值不在数字，而在归因和动作。

## 指标口径

口径必须先声明再计算，同一份报告内不得混用：

| 指标 | 公式 | 口径要点 |
|---|---|---|
| ROAS | 广告收入 / 广告花费 | 广告收入是否含税、是否扣退款必须写明 |
| ACOS | 广告花费 / 广告收入 | 与 ROAS 互为倒数，报告里用哪个保持全篇一致 |
| TACOS | 广告花费 / 总销售额 | 分母含自然单，用于看广告对整体的拖累 |
| 保本 ROAS | 1 / 毛利率（不含广告费） | 低于此线的组在亏钱 |
| 保本 ACOS | 毛利率（不含广告费） | 与保本 ROAS 等价 |
| CTR | 点击 / 曝光 | 素材吸引力 |
| CVR | 订单 / 点击 | 承接与价格 |
| CPC | 花费 / 点击 | 出价与竞争 |
| CPA | 花费 / 订单 | 单量成本 |
| 毛利 | (售价 − 商品成本 − 履约费 − 平台佣金 − 税费) × 销量 | 各费率取自阶段 1 的费率表 |
| 净利 | 毛利 − 广告花费 − 退款 − 其他费用 | 复盘看净利，不要只看 ROAS |
| 贡献占比 | 该组净利 / 总净利 | 判断资源集中度 |

## 复盘流程

取数 → 口径核对（含税、退款、归因窗口）→ 计算 → 分组对比（campaign / SKU / 日期 / 站点）→ 归因 → 结论 → 动作 → 待人工确认事项。

## 归因框架

把结果拆成量与率的乘积，逐层定位是哪个环节变了：

- `GMV = 曝光 × CTR × CVR × 客单价`
- `毛利变化 = 销量 × (客单价 − 单位成本) − 广告花费 − 退款 − 履约与税费`
- `ROAS 变化` 拆成 `CVR 变化`、`CPC 变化`、`客单价变化` 三项，分别对应素材、竞争、定价三个可动作的方向。

归因结论必须落到「哪个环节、变化多少、下一步动谁」，只说「整体表现不好」没有价值。

## 异常阈值

默认阈值（可在报告里覆盖，但改的时候要写理由）：

- 环比波动超过 ±20%
- ROAS 低于保本线
- 花费达到单组预算的 60% 以上且零转化
- 退货率或退款额环比翻倍
- 某 SKU 贡献占比超过 40%（集中度风险）
- 数据缺失行占比超过 5%（口径不可信的信号）

## A/B 对照与上线验证

- 离线对照：同一批历史数据跑新旧规则，看结论差异与差异来源。
- 在线对照：上线前后两个时间窗，必须控制季节、大促、断货、调价等变量，否则结论只能作参考。
- 显著性：样本量不足或窗口含大促时，`confidence` 不超过 0.6 并写明原因。
- 记录每轮迭代的预期改进指标，下一轮复盘先回答「上一轮改的东西有没有生效」。

## 周报结构

结论先行，模板固定：

1. **三条结论**（赚钱的、亏损的、需要人工决策的，各一条，每条带数字）
2. **核心指标表**：花费、收入、ROAS、ACOS、TACOS、净利 + 环比
3. **分组明细**：按 campaign 或 SKU，含花费占比与净利贡献
4. **归因分析**：量/价/率三层拆解，指出变化主因
5. **下周动作**：加预算 / 关停 / 换素材 / 调价，每条写清责任人与判断依据
6. **待人工确认**：超阈值、数据存疑、需资金审批的事项

## 脚本用法

```bash
python3 scripts/roi_review.py 投放明细.xlsx --group-by campaign \
  --compare 上期明细.csv --out-md review.md --out-json review.json \
  [--gross-margin 0.35] [--breakeven-roas 2.86] [--threshold 0.2]
```

脚本做确定性核算与异常标记，归因文字和下周动作由你根据输出撰写。`--gross-margin` 用于在缺少成本列时推导保本 ROAS——这种情况下必须在 `assumptions` 里声明用的是经验毛利率而非实际成本。

## 常见坑

- 广告收入与总销售额混用，导致 TACOS 与 ACOS 口径打架。
- 归因窗口不同（7 天点击 / 1 天浏览）导致同一活动在两个后台数字不一致。
- 自然单与广告单重叠，直接相加会重复计算。
- 退款未扣：大促后退货高峰会让上月 ROAS 看起来虚高。
- 优惠券、平台补贴、运费收入没计入，毛利算偏高。
- 混合币种未换汇就聚合。
- 跨期：月初月末的观察窗与平台结算周期不对齐。
- SKU 与 ASIN 口径混用（多变体 listing 合并统计时尤其明显）。
