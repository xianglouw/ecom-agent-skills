# 阶段 4（生产侧）：分镜、检查、多语种与生成

本文件解决「怎么出素材」：分镜骨架、前三秒检查项、多语种适配、把提示词交给生成平台。
「做哪种形态」见 [creative-stack.md](creative-stack.md)；投放结构、出价与止损由 `ecom-ads-plan` 负责。

## 前置条件

- **Listing 已上线**：落地页、价格、库存、促销到位。素材先于落地页生成的代价是点击进来价格对不上，退款和差评反噬。
- **产品定义齐**：品类、目标人群、3 个以内卖点、证明材料、CTA 利益点。缺卖点的素材只能拍成产品展示，钩子无从谈起。
- **风格库就绪**：投放市场的语种、语速上限、平台、节奏、画面、出镜者、场景、调性、禁忌——**必须来自风格库文件**，不能靠模型凭印象编。
- **合规词表就绪**：绝对化用语、功效宣称、平台特殊限制。

## 环节与工具

每段用最适合的模型，不要指望一个模型端到端。**本技能负责写稿与检查，用什么工具由用户定**：

| 环节 | 本技能交付 | 出片靠什么 |
|---|---|---|
| 关键帧 / 静图 | 画面描述 + 首帧要求 | 文生图、图生图工具 |
| 视频生成 | 分镜表 + 生成提示词 | 见下方「生成侧」 |
| 配音与字幕 | 分镜表里的口播与字幕列（含语速预算） | TTS、数字人 |
| 剪辑与合成 | 镜头顺序、时长、字幕文本 | 剪辑软件或自动化流水线 |
| 上传归档 | 素材编号与台账字段 | 素材库 / 广告后台上传工具 |

工具能力以实际可用版本为准；本文件规定的是**各环节的输入输出契约**，换工具不影响流程。
数字人、声音克隆、换脸、混剪、素材库、去水印这些外部能力怎么选、红线在哪，见 [creative-stack.md](creative-stack.md)。

## 分镜骨架

固定五段，第一镜永远是 3 秒钩子，不允许把钩子往后挪：

| 镜头 | 15s | 21s | 30s | 作用 |
|---|---|---|---|---|
| 1 钩子 | 0–3s | 0–3s | 0–3s | 拦住刷走 |
| 2 痛点场景 | 3–7s | 3–8s | 3–10s | 让目标人群确认「说的是我」 |
| 3 产品演示 | 7–11s | 8–14s | 10–18s | 产品怎么解决问题，实拍优先 |
| 4 证明 | 11–13s | 14–18s | 18–25s | 销量、评价、实测、资质 |
| 5 CTA | 13–15s | 18–21s | 25–30s | 只留一个动作与利益点 |

同一 SKU 至少出 2 个不同钩子的版本，素材之间只变一个变量，否则测不出结论。
钩子类型见 `examples/hook_patterns.csv`（编码、首帧要求、口播与字幕模板、留存说明），按品类继续扩充。

## 前三秒留存检查项

`video_brief.py` 自动跑这十项，逐条给出通过与否：

| 检查项 | 规则 | 不通过的后果 |
|---|---|---|
| 首帧有主体 | 第一帧就是产品主体、使用动作或冲突画面 | 前 3 秒划走 |
| 禁止开场方式 | 不用 logo、片头动画、黑屏、空镜、慢镜头、静态白底图开场 | 完播率断崖 |
| 前 3 秒有动态 | 首帧描述里必须含动作或画面变化 | 像图片轮播，点击率低 |
| 字幕可读 | 前 3 秒必须有字幕，静音刷到的用户要能看懂 | 静音环境下等于没讲 |
| 口播讲得完 | 3 秒口播不超过目标语种语速上限 | 话没讲完就被划走 |
| 字幕放得下 | 前 3 秒字幕不超过单行长度（默认 ≤20 全角字位） | 关键信息被折行切碎 |
| 语种一致 | 产品表与风格库语种对得上，配音字幕落地页同语种 | 转化断崖 |
| 钩子类型明确 | 取自钩子模板库并写明留存理由 | 素材全靠感觉，无法复盘 |
| 已本地化 | 文案是目标市场语言，机器翻译腔要重写 | 本地用户一眼看出是外来卖家 |
| 合规 | 无绝对化用语、无功效承诺、无未证实对比 | 审核不过或被罚款 |

**常见失败模式**：品牌介绍放开头、前 3 秒讲参数、一条视频塞 5 个卖点、钩子与落地页承诺不一致、只有配乐没有口播字幕、全程一个长镜头。

## 多语种适配

换语种不只要翻译，下面按顺序过一遍，能挡掉大多数「翻译了但还是不像本地素材」的问题。

### 语种怎么填

短代码与地区变体（`vi`、`vi-VN`、`pt-BR`）、英文名（`Vietnamese`）、中文名与简称（`越南语`、`泰文`）、
平台后台的原生写法（`Tiếng Việt`、`日本語`、`ภาษาไทย`、`العربية`）都认，共 53 个语种、400+ 种写法。

认不出的写法标 `language_unrecognized` 并按保守默认值折算，不静默当成别的语种；产品表与风格库语言冲突标 `language_conflict`（会直接导致配音与字幕对不上）；定不下来标 `language_missing`，此时语速预算是**按工作语言算的占位值**，报告里会明确标注。

### 计量单位与语速上限

口播能不能在 3 秒内讲完，**不同语种算法不一样**，混用会得出错误结论：

| 语种类型 | 计量方式 | 内置上限（每秒） |
|---|---|---|
| 无空格分词 | 按字符 | 中文 4.5、日文 5.5、韩文 5.0、泰文 4.5、高棉文 4.0、老挝文 4.0、缅甸文 3.5 |
| 空格分词 | 按词 | 英语 2.6、西语 3.0、越南语 3.5、德语 2.4、俄语 2.2（其余 40+ 语种走同类折算） |

- 数值是**广告口播的经验上限**（比日常语速慢约 10–20%），不是语言学结论，会随主播、品类、平台浮动。
- 优先级：`--speech-rate vi=3.5` > 风格库的「语速上限」列 > 内置表。同一语种在不同市场语速不同时（墨西哥西语快于智利西语），写进风格库按市场覆盖。
- **以实际试听为准**：配完音拿秒表量前 3 秒，超了就砍词，不要加快语速硬塞——语速一快，完播率与信任度一起掉。
- 文案里未填的创意位按 2 个单位计入长度，所以**本地化后必须按目标语种复测**，不能沿用中文草稿的结论。

### 书写系统与排版

- **断行**：中日韩泰不用空格分词，不能按空格断行；泰文、高棉文、老挝文、缅甸文要在剪辑软件里手动确认断行位置。
- **方向**：阿拉伯语、希伯来语、乌尔都语、波斯语是 RTL，字幕位置、标点方向、与图标的相对位置都要镜像对待。
- **字体**：泰文、缅甸文、高棉文、阿拉伯文、天城文需要专门字体，缺字形会烧出方块。
- **字符膨胀**：同一句文案，德语、俄语、芬兰语通常比英语长 20–35%，用目标语种字号上限反过来约束文案长度。
- **标点与数字**：中文标点出现在目标语字幕里是「机翻感」最明显的信号；千分位与小数点、货币符号位置、日期顺序都要按当地写法。

### 配音

- **口音优先于语种正确**：拉美西语 vs 西班牙西语、巴西葡语 vs 欧洲葡语，用错口音本地用户第一句就听出不是给他们拍的。
- **配音与字幕必须同语种**，脚本会在语种冲突时标出来。
- 小语种（高棉语、老挝语、缅甸语）TTS 质量差异大，先试听再批量生产，不行就换真人。

### 本地化交付清单

brief 里固定附五项：前 3 秒钩子口播与字幕按预算重写 → 全片字幕口播改用目标语标点与数字格式 → 配音换本地口音且与字幕同语种 → 字幕按目标语种断行与方向排版 → 画面里的包装、招牌、界面文字一并换成本地语言。

## 地区与人群适配

同一个产品在不同市场，素材要换的不只是语言：

- **平台与节奏**：TikTok / Reels 更吃强动态与快切；信息流图文版位可以缓一些，但钩子逻辑不变。
- **场景与人物**：出镜者年龄、家庭结构、居住环境要贴近当地真实生活，明显非本地的场景会掉转化。
- **价格与促销**：当地币种与当地常见话术（免运费、分期、买二送一）优先于「立减 10%」这类通用表达。
- **禁忌**：宗教、政治、国旗、地域玩笑、体型与肤色玩笑，列进风格库的禁忌字段，生成与剪辑前各查一次。

**风格库必须可追溯**：每条结论带来源（本地达人素材复盘、平台后台数据、当地团队反馈）与获取日期，不能靠模型印象编造——风格库缺哪个市场，脚本直接标 `high`，不套用其他市场习惯。

## 生成侧：把提示词接到视频生成平台

写好的提示词有两种交付方式，按手上的工具选：**手动交付**（把分镜表的 `visual_prompt` 列粘到平台网页或客户端，默认）或**直连生成**（`video_render.py` 按 `providers.json` 组装请求，提交 → 轮询 → 取回成片 → 记台账）。

**选哪个模型由用户决定**：脚本用 `--list-providers` 列平台与默认模型，用户用 `--provider` 选平台、`--model` 覆盖版本。本技能不替用户选模型、也不判断哪家更便宜——只保证**提示词按这个平台的参数名被正确装进请求**。

```bash
python3 scripts/video_render.py --list-providers                       # 看平台、默认模型、所需环境变量
python3 scripts/video_render.py storyboard.csv --provider ark --check  # 验凭据，不花钱
python3 scripts/video_render.py storyboard.csv --provider ark \
  --assets SKU-101_MX_H01_9x16_15s_v1 --shots 1 --print-request        # 看实际请求体（密钥打码）
python3 scripts/video_render.py storyboard.csv --provider ark --max-clips 8 --confirm \
  --outdir renders --out renders.csv --out-xlsx renders.xlsx --out-json renders.json
```

预置 12 个平台（`mock` 离线演示 / `ark` 火山方舟 / `dashscope` 通义万相 / `kling`、`kling-i2v` 可灵 / `minimax` 海螺 / `gemini` Veo / `openai` Sora / `runway` / `luma` / `replicate` / `fal`）。加平台、换模型、改参数只动 `providers.json`，或用 `--provider-file 我的配置.json` 传覆盖配置。

**各平台的坑**（配置已按 2026-09-14 的端点形状写好）：`kling` 走 JWT，要同时给 Access Key 与 Secret Key，图生视频的 `image` 要纯 base64 不带 `data:image` 前缀；`dashscope` 要 `X-DashScope-Async: enable` 头；`minimax` 查询返回 `file_id`，还要再调一次换下载地址；`gemini` 用 `x-goog-api-key` 头而非 Authorization，失败信息在 `error` 字段（配了 `error_path`，失败立刻判定不等超时）；`openai` 提交后要再取 `/v1/videos/{id}/content` 才是文件本体；`runway` 必须带 `X-Runway-Version` 头；`luma` 状态字段是 `state`；`fal` 的鉴权头是 `Authorization: Key ...` 而不是 Bearer。

**参数会变，以官方文档为准。** 各平台参数名、模型名、计费口径随版本变化，正式投产前用 `--check` 与 `--print-request` 核对一次。

**花钱这件事**：生成按条计费，脚本不掌握实时单价，所以只做三件事——`--max-clips`（默认 10）硬截断数量、不加 `--confirm` 一个字节都不发、每笔的提交时间与任务 ID 都进台账。视频模型多按固定档位计费（常见 5 秒 / 10 秒一档），`--use-shot-seconds` 按分镜秒数生成但**只取更大的那个值**，不会短于 `--duration`。放量前先压到 1–2 条验证。

**首帧图**：图生视频必须要，其余平台有则更好——先出首帧再出视频比纯文生稳定得多。查找顺序：分镜表里的 `first_frame` / `first_frame_path` 列 → `--first-frame-dir` 下的 `素材名_镜头号.png` → 同目录 `素材名.png`。也认 `.jpg` / `.jpeg` / `.webp`，本地图片按 `--max-image-mb`（默认 8MB）限制体积；命名对不上时明确告诉你**缺哪个文件名**，不静默跳过。

**断点续跑**：已成功且成片还在的镜头重跑时默认跳过，不重复花钱；全部重生成加 `--overwrite`。

## 生成与验收

- **一次一个镜头**：多镜头一次性生成通常连不上、动作也乱，按分镜逐镜生成再拼接。
- **先出首帧再出视频**：钩子镜头先用图模型出 3–5 张候选首帧，选定后再图生视频，比纯文生稳定得多。
- **验收标准**：产品外观与实物一致、无多指畸形手、文字无乱码、口型与配音对得上、前 3 秒无黑帧与静音、字幕无错别字、时长与版本一致。
- **不通过就回炉**：改提示词里的动作与镜头语言再生成，不要靠剪辑掩盖生成缺陷。

## 复盘口径

素材级指标：3 秒播放率、完播率、CTR、CPC、CVR、CPA、ROAS。判优顺序是**先用 3 秒播放率筛钩子，再用 CTR 筛封面与前 3 秒组合，最后用 CVR/ROAS 判断承接与定价**——三个环节混在一起看，只会得出「素材不行」这种没法行动的结论。

A/B 纪律：一次只改一个变量；样本不足（未跑出 3–5 个转化）不下结论；同一钩子在不同市场分开统计，不要合并。指标定义与周报口径见 `ecom-roi-review`。

## 脚本用法

```bash
python3 scripts/video_brief.py products.csv --styles market_styles.csv \
  --hooks hook_patterns.csv --banned banned_words.csv \
  --duration 15 --ratio 9:16,16:9 --hooks-per-sku 2 --speech-rate vi=3.5 \
  --out storyboard.csv --out-md brief.md --out-json brief.json --quarantine brief_issues.csv
```

| 参数 | 作用 |
|---|---|
| `--styles` | 市场风格库（语种 / 语速上限 / 平台 / 节奏 / 画面 / 出镜 / 场景 / 调性 / 禁忌） |
| `--hooks` | 钩子模板库，脚本按序轮换，避免所有 SKU 用同一个开头 |
| `--banned` | 禁用词表，扫描卖点、证明、CTA 与全部字幕口播 |
| `--actions` | 自定义动作词表，扩充首帧动态检查的判定词 |
| `--duration` / `--ratio` | 成片时长（15/21/30）与画幅，可传多个比例 |
| `--hooks-per-sku` | 每个 SKU × 市场出几条钩子版本 |
| `--speech-rate` | 按语种覆盖内置语速表，如 `vi=3.5,ja=6`，优先级最高 |
| `--working-language` | 钩子模板与分镜文案当前用的工作语言，默认 `zh`；文案已本地化后改这里 |
| `--caption-limit` | 前 3 秒字幕单行可容纳的全角字位数，默认 20 |

多语种的工作方式是：**先用工作语言把分镜和长度跑通，再按目标语种本地化，最后按 brief 里的口播预算复测前 3 秒**。脚本按文案实际出现的书写系统判断「还是草稿」还是「已本地化」，再决定用哪套语速规则——本地化后直接重跑一次就能得到目标语种的结论。

钩子模板库是合并加载、按行号轮换的：要按语种用不同模板，就按语种分组分批跑（用 `--markets MX,CL,CO` 这类过滤），或先用工作语言跑完整套分镜再逐条本地化。
