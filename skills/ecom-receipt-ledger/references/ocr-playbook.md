# 手写单据识别作业手册

识别这一步由多模态模型完成（Agent 自带的视觉能力，或 `see` / `claude-vision-skill` 这类视觉工具）。手册定四件事：**怎么拍**、**怎么问**、**认到什么程度要停**、**字迹潦草怎么加固**。

> 字迹潦草、涂改、简写混排的单据，先看 [handwriting-hardening.md](handwriting-hardening.md)：那里有四遍读法、候选值机制与补拍指令模板。本手册的提示词模板已经按那套流程写好。

## 一、拍照规范（决定识别上限）

| 项 | 要求 | 反例 |
|---|---|---|
| 平整 | 单据摊平，不要折叠、不要捏着拍 | 卷边遮住金额小数位 |
| 正对 | 镜头垂直于纸面，四角都进画面 | 斜拍导致右列数字变形 |
| 光线 | 均匀自然光或顶灯，避免阴影与反光 | 手影盖住「数量」列、白纸反光过曝 |
| 清晰 | 对焦在文字上，小字看得清 | 拍完自己都认不出「8」还是「3」 |
| 一单一拍 | 一张单据一张照片，别一次拍一叠 | 叠在一起只拍到最上面那张 |
| 分辨率 | 长边 ≥ 1600px | 微信压缩过的缩略图 |
| **分区拍** | 先拍一张全貌定骨架，字迹潦草的行再靠近单独拍一张特写 | 只拍一张远景，小字全靠猜 |
| **多角度** | 同一张单据至少两个角度各拍一张，识别时交叉验证 | 拍糊了凑合上传 |

补拍比返工便宜：**需要特写的行超过 5 行，整张重拍更快。**

## 二、识别提示词模板（六段式，可直接复用）

模板按「先骨架、后数字、再交叉、最后自检」组织，对应 [handwriting-hardening.md](handwriting-hardening.md) 的 P0–P4。

```text
【角色】你是手写采购/销售单据的录入员，只做转录，不做业务判断，不补全没写的内容。
【任务】分两遍识别，再合并输出：
  第一遍（只读骨架）：每张照片有单据几张、每张几行、行号起止、单据号、日期、方向、有无圈号分组（如 ②③）、有无划掉的行。
  第二遍（逐行抠数）：按行裁切放大，每行只读取 品名 / 数量 / 单价 / 金额 四个格子，逐位念出数字。
【输入】用户提供的单据照片（可多张）；拍摄说明：{日期范围 / 店名 / 是否有连笔简写}
【输出格式】纯 JSON，不要解释文字：
[{
  "photo": "照片文件名",
  "doc_no": "单据号，没写就空字符串",
  "date": "YYYY-MM-DD；只写月日时给 MM-DD 并在 note 里说明",
  "direction": "采购 或 销售；判断不了填 unknown",
  "party": "对方名称（供应商/客户），没有就空",
  "skeleton": {"rows_counted": 骨架数出来的行数, "row_numbers": "实际出现的行号，如 1-3,5-9,12-13",
               "group_marks": "圈号/打勾/画叉等记号及所在行", "void_rows": "疑似划掉的行号"},
  "elements": [{
    "row_no": "单据上的行号",
    "item_raw": "品名，照抄手写原文（含简写），不要翻译成标准型号",
    "spec": "规格/容量/颜色，没有就空",
    "qty": 数字或 null,
    "unit_price": 数字或 null,
    "amount_written": 单据上写的金额，没有就 null,
    "candidates": ["读不准时给出最多 3 个候选写法，按可能性排序；读得准就是空数组"],
    "field_confidence": {"item_raw": 0~1, "qty": 0~1, "unit_price": 0~1, "amount_written": 0~1},
    "confidence": "取上面四个字段里的最低分，不要取平均"
  }],
  "total_written": 单据上的合计数，没有就 null,
  "unreadable": ["看不清的字段，写成 行号+字段名，如 '5 行 单价'"],
  "self_check": {"rows_match": "识别行数与 skeleton.rows_counted 是否一致", "diff_note": "差在哪里"},
  "note": "存疑点，例如「第 5–9 行共用一个圈号 ②」"
}]
【约束】
- 看不清的字段写 null，禁止推测、禁止脑补；数字连笔（3/8、5/6、0/6）必须给候选值而不是选一个。
- 任何格子只要给了 candidates，该字段 confidence 必须 ≤ 0.6。
- 圈号（②③）、打勾、画叉是记号不是数据：圈号不填进数量，打勾不算删除线，拿不准写进 note。
- 行号跳号（如 1,2,3,5）要在 note 里点名，不要自动补行、不要把行号当成数量。
- 禁止把「合计」行当成一条明细；禁止把金额列的数字搬进单价列。
- item_raw 保留手写简写原样（如 14pm改17pm、15DD屏幕、XR），不要翻译。
- 数字只认阿拉伯数字与常见中文数字，符号（¥、元）不写进值里。
- field_confidence 反映「这个格子看得清不清」，不是「业务上合不合理」。
【自检】输出前逐张确认：行数与骨架一致、日期可解析、数量×单价与金额是否对得上；对不上或行数不一致的在 self_check 里点名。
```

**整批照片的用法**：一次给 5–10 张，要求输出 JSON 数组；每张单据里带上照片文件名，方便回链凭证。识别完把 JSON 拍平成表格（每行 = 一条明细 + 所属单据号 + 照片文件名），就是本技能要求的输入表。

**两遍读法怎么落地**：同一批照片跑两次——第一遍按上面的模板走，第二遍把任务换成「按列读：先读完整列的数量，再读完整列的单价」，两次结果逐字段比对；不一致的格子进「候选值」列。只跑一遍的结果，潦草单据不建议直接入账。

## 三、置信度怎么定

| 分值 | 场景 | 后续 |
|---|---|---|
| 0.95–1.0 | 印刷体或清晰手写，数字无歧义 | 直接入账 |
| 0.80–0.95 | 手写但清楚，个别字需要上下文确认 | 正常入账，抽样复核 |
| 0.60–0.80 | 有连笔、涂改、淡笔迹，或简写没见过 | 进「异常行」，对照原图复核 |
| < 0.60 | 有关键字段靠猜，或给了候选值 | **不进日结**：进隔离清单与补拍清单 |

同一张单据里各行的 `confidence` 分别给，不要整张给一个平均分。脚本两条线：`--low-confidence 0.75` 告警、`--confidence-floor 0.6` 隔离。

## 四、认到什么程度要停下来

- **金额列与合计数对不上**：先别改数据，回到原图看图，确认是「单据写错」还是「识别错」——两者处理方式不同（前者记录差异并找对方确认，后者修识别结果）。
- **同一天同一张单据被拍了两次**：会产生两笔一模一样的记录，交给「疑似重复」规则处理，人工确认。
- **连续多行识别置信度低于 0.7**：不是数据的错，是拍照的错，重拍比逐行纠错快。
- **手写简写批量认不出**：把新简写补进 [alias-dictionary.md](alias-dictionary.md)，下一批就自动命中。
- **单价看着离谱**：用 `--price-ref` 接一份历史价格库，让脚本标出偏离行，再回看原图——比人肉逐行对价格快得多。

## 五、照片归档约定

```text
photos/
└── 2026-09/
    ├── IMG_0901_采购单.jpg      # 建议命名：IMG_月日_单据类型（可带流水号）
    ├── IMG_0901_销售单.jpg
    └── IMG_0903_销售单_2.jpg
```

- 文件名进 `photo_path` 列，脚本按 `--photos-dir` 拼路径、按 `--photos-base` 拼云端地址。
- 潦草行的特写照片建议命名为 `IMG_0902_采购单_第5行特写.jpg`，补拍时一眼能找到对应关系。
- **原图不要压缩后替换**：查验时看的就是那张原图，压缩过的图在纠纷里不作数。
- 按月分文件夹，跨月对账时不用在几千张图里翻。
