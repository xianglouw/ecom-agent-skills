# 单据明细字段契约

识别结果表必须能被脚本认出来。列名支持中英文别名自动识别（见共享别名库），认不出来时用 `--map 原列名=标准字段` 手工指定。

## 字段表

| 标准字段 | 中文列名（任选其一） | 必填 | 类型 | 说明 |
|---|---|---|---|---|
| `date` | 日期 / 单据日期 / 交易日期 | ✅ | 日期 | `2026-09-03`、`2026.9.3`、`9.3`（补 `--default-year`）、`20260903` |
| `direction` | 业务方向 / 类型 / 方向 | ✅ | 枚举 | 采购或销售；写法可写 进货/入库/出货/应收 等，脚本自动归一 |
| `doc_no` | 单据号 / 票号 / 单号 | | 文本 | 一张单据多行时每行都写同一个单号，便于按单核对 |
| `item_raw` | 手写原文 / 品名原文 / 手写品名 | ✅ | 文本 | **照抄手写内容，不要自行改写**，标准化交给映射表 |
| `item_std` | 标准品名 | | 文本 | 已手工确认标准名时直接填，填了就不再走映射表 |
| `category` | 类别 / 品类 | | 文本 | 整机 / 屏幕总成 / 电池 / 主板 / 配件…… |
| `spec` | 规格 / 颜色 / 容量 | | 文本 | `256G 深空黑`、`原装拆机` |
| `qty` | 数量 | ✅ | 数字 | 必须为正数；写成「2台」时数字会被解析出来 |
| `unit` | 单位 | | 文本 | 台 / 片 / 个 / 条；缺省用 `--unit` |
| `unit_price` | 单价 | ✅ | 数字 | 与金额同币种、同含税口径 |
| `amount_written` | 手写金额 / 单据金额 / 小计 | | 数字 | 单据上写的金额；缺省时按 数量×单价 补齐并标注 |
| `photo_path` | 凭证 / 照片 / 图片 / 附件 | | 文本 | 文件名或相对路径；配合 `--photos-dir` 定位，或配 `--photos-base` 生成云端链接 |
| `confidence` | 识别置信度 / OCR置信度 | | 数字 | 0–1 或 0–100；低于 `--low-confidence` 的行会被点名复核 |
| `supplier_name` | 供应商 / 供货商 | | 文本 | 采购单填供货方，销售单可留空或填客户 |
| `remark` | 备注 | | 文本 | 识别时的存疑点写在这里，一并带进台账 |

## 三条硬约束

1. **手写原文不许美化。** `item_raw` 里写「14pm改17pm」这种原样文字，标准化是映射表的职责。改了原文就再也对不回原始单据。
2. **认不出就留空。** 字迹看不清的字段写 `unknown` 或留空，并在 `confidence` 上体现，不许用经验值填坑——填错的数字比缺失的数字危险得多。
3. **一张单据一行：** 单据上 3 行明细就 3 行记录，第 1 列都写同一个 `doc_no`；不要把多行压成一行、也别把合计行录成明细行（合计行会被当成重复销售）。

## 映射表字段

`--alias` 指向的简写映射表：

| 列 | 必填 | 说明 |
|---|---|---|
| 简写 / 手写原文 | ✅ | 归一化后比较：忽略大小写、全角半角、空格 |
| 标准品名 | ✅ | 标准库名称，后续统计盘点都用它 |
| 类别 | | 整机 / 屏幕总成 / 电池…… |
| 规格 | | 手写单没写规格时用这里的默认值补 |

## 识别结果什么时候算「够用」

| 情况 | 判定 | 处理 |
|---|---|---|
| 日期、方向、手写原文、数量、单价都能读出来 | 可入账 | 正常跑日结 |
| 其中一项读不出 | 部分可入账 | 该行进隔离清单，其余照常出日结 |
| 日期或方向读不出的行 > 20% | 不可入账 | 先修拍照质量与识别提示词，别硬跑 |
