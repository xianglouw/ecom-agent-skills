# 手写简写 → 标准品名 映射字典

手写单靠简写省时间，代价是「同一个东西写出七八种样子」。映射表就是把它们收成一个标准名，让后面的盘点、毛利、复购统计能算得下去。

## 怎么用

1. 先跑一次日结，看「待映射简写」工作表里冒出来什么；
2. 把高频简写补进映射表（`简写,标准品名,类别,规格`），一个简写一行；
3. 重跑，命中率上升；几轮之后基本不再出现未映射行。

`examples/alias_map.csv` 是一份可直接改的模板。

## 匹配规则（少写很多重复行）

| 规则 | 例子 | 结果 |
|---|---|---|
| 忽略大小写 | `XR电池` / `xr电池` | 同一个键 |
| 忽略空格与全角半角 | `XR 电池` / `XR电池` | 同一个键 |
| 忽略标点括号 | `屏幕(总成)` / `屏幕总成` | 同一个键 |
| 精确优先 | 表里同时有 `14pm` 与 `14pm改17pm` | 手写「14pm改17pm」命中长的那条 |
| 最长子串兜底 | 表里有 `15DD屏幕`，手写「15DD屏幕 原装」 | 命中 `15DD屏幕`，后续文字进备注 |
| 匹配不上不猜 | 手写「神奇配件」 | 标「未映射」，进待映射清单 |

## 起步词表（照着改成自己店的写法）

**判断原则：映射表是「本店的黑话词典」，默认词表只是起点。** 同一个简写在不同店可能指不同东西，尤其是 `p`、`pm`、`DD` 这类字母后缀。

### 机型与代称

| 常见简写 | 通常含义 | 备注 |
|---|---|---|
| `X` / `XR` / `XS` / `XSmax` / `11` / `12` / `13` / `14` / `15` / `16` | iPhone 机型 | 数字即代数，前面常带型号后缀 |
| `pm` / `PM` / `Max` | Pro Max | `14pm` = iPhone 14 Pro Max |
| `p` | Pro 或 Plus（**有歧义**） | 必须在本店词表里写死，别指望 AI 猜 |
| `8P` / `7P` / `6SP` | iPhone 8 Plus / 7 Plus / 6s Plus | `P` = Plus 的场景 |
| `13mini` / `12mini` | 小屏机型 | |
| `SE2` / `SE3` | iPhone SE 第二代 / 第三代 | |
| `改` | 改装（换壳/改型） | `14pm改17pm` = 用 14 Pro Max 主板 + 17 Pro Max 外壳总成，**必须整条写进映射表**，不能只映射到 14pm |

### 零件与工艺

| 常见简写 | 通常含义 |
|---|---|
| `屏` / `屏幕` / `总成` | 屏幕总成 |
| `DD屏` / `DD线` | 特定排线规格的屏幕（按本店供应商口径写标准名） |
| `原装` | 原厂件 |
| `拆机` | 从整机上拆下的原装件 |
| `后压` | 原装内屏 + 更换外层玻璃 |
| `国产` / `组装` | 第三方配件 |
| `电池` / `电芯` | 电池总成 / 单电芯 |
| `排线` / `尾插` / `尾插排线` | 尾插排线总成 |
| `主板` / `板` | 主板（常带容量与网络版本，如 `12 128G 国行`） |
| `后摄` / `前摄` / `后摄总成` | 摄像头模组 |
| `面容` / `FaceID` | 面容识别模组 |
| `中框` / `后壳` / `后盖` | 中框总成 / 后壳 |
| `卡托` / `听筒` / `喇叭` / `震子` | 小件 |
| `WIFI天线` / `信号排线` | 天线类 |

### 成色与交易词

| 简写 | 含义 | 建议标准名写法 |
|---|---|---|
| `靓机` / `准新` | 成色好 | 机型 + 成色（写在规格列，别写进品名） |
| `小花` / `大花` | 轻微 / 明显使用痕迹 | 同上 |
| `官换` / `官修` | 官方换机 / 官方维修机 | 机型 + 标注 |
| `有锁` / `无锁` | 网络锁状态 | 型号 + 锁状态 |
| `资源机` / `BS机` | 渠道机 | 按本店口径写 |

## 口径建议

1. **标准名写成「品牌 + 型号 + 部件 + 关键参数」**：`iPhone 14 Pro Max 改装 17 Pro Max 后壳总成`，不要只写「14改17」——半年后自己都要回忆。
2. **成色、锁状态、产地放规格列**，不要塞进品名，否则统计时同一个部件会被拆成十几个「不同商品」。
3. **改机、翻新机单独建条目**，不要与全新件合并，毛利差异极大。
4. **映射表进版本管理**：谁改了什么、什么时候改的能查得到，避免口径悄悄漂移。
