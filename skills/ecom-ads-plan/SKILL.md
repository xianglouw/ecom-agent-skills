# 阶段 5 · 广告投放方案与投流结构

从选品和素材出发，产出**可以直接在广告后台照着执行**的投放结构、出价预算与止损规则。投放动作本身由人工在平台后台完成——本技能只交付方案、脚本与判定规则，不代替人工改动任何账户设置。

完整方法论见 [references/ads-video.md](references/ads-video.md)。

## 投放前必须确认

缺任何一项都先回问，否则只能给通用建议：

- **平台与版位**：TikTok / Meta / Google / Amazon Ads / Shopee Ads，视频版位与图文版位策略不同。
- **投放目标**：测品 / 放量 / 清库存 / 拉新 / 保 ROAS——目标不同，出价与预算分布完全不同。
- **经济模型**：客单价、商品成本、履约费、平台佣金、退货率 → 算出**保本 ROAS = 1 / 毛利率**，这是出价的锚。
- **素材库存**：现有视频数量、时长与比例、能否批量产出（决定能测几轮）。
- **承接与库存**：Listing / 落地页是否就绪、库存够不够放量、价格与促销是否到位。
- **合规**：平台广告政策、素材版权与音乐授权、达人合作披露要求。

## 交付物

1. **投放结构表**：三级命名规范 `campaign = {平台}_{站点}_{目标}_{品类}_{开始日期}`、`ad_group = {受众或素材方向}_{出价方式}`、`ad = {素材编号}_{版本}_{比例}_{时长}`；一个 campaign 只测一个变量维度（素材 / 受众 / 出价三选一）。
2. **预算与出价表**：`CPC上限 = 客单价 × CVR × 毛利率`、`CPA上限 = 客单价 × 毛利率`，保本 ROAS 作为硬约束，低于它的组不追加预算。
3. **放量节奏**：第 1 轮广度测素材（多条小额）→ 第 2 轮对优胜素材做受众与出价组合 → 第 3 轮放量；每次加预算不超过 30%，避免重置学习期。
4. **止损与判优阈值表**：花费到单素材预算 X% 且无转化 → 关停；CTR 显著低于同组均值且曝光足够 → 暂停素材；ROAS 连续两个观察窗低于保本线 → 降预算或换素材方向；素材出现违规警告 → 停投并排查合规。
5. **待人工执行清单**：新建 campaign、上素材、设预算、开投、违规处理，逐条写清谁执行。

## 数据看板与阈值

曝光、点击、CTR、CPC、CVR、CPA、花费、广告收入、ROAS、ACOS、TACOS、完播率、3s 留存、加购率、退货率。

阈值必须按品类和站点基线设定，**先取该店铺自身近 30 天基线再看偏离度**，不要直接套用通用经验值。

## 风险与人工边界

| 等级 | 本阶段场景 | AI 权限 | 人工权限 |
|---|---|---|---|
| 高 | 超阈值预算、调价、新账户首次放量、素材命中平台广告政策、涉及资金与账户设置的动作 | 只出方案 + 阈值 + 待办 | 在后台执行并终审 |
| 中 | 低于保本 ROAS 的组、冷启动期频繁调整、归因口径变化、样本量不足以判定 | 出结论 + 风险标注 | 抽样复核 |
| 低 | 命名规范、结构编排、阈值表整理、报告撰写 | 直接执行 | 事后抽查 |

**不自动动钱、不动平台设置。** 改预算、改出价、开停广告、调整账户配置，只输出方案、判定与待办清单，由人在后台执行。不编造平台流量与转化数据；阈值来自店铺自身基线或用户给定口径。

## 常见坑

- 样本不足就关停——少于 3 个转化的判定基本是噪音。
- 一个 campaign 同时改素材、受众、出价，最后测不出哪个变量有效。
- 冷启动期频繁改预算，反复重置学习期，永远跑不出量。
- 只盯 ROAS 不看退货率，退货一结算毛利变负。
- 归因窗口差异导致与后台数据对不上，复盘前先对齐口径。

## 输出契约

与其他跨境电商技能共用同一个 JSON 信封，便于跨阶段串联、工单回写与事后追责：

```json
{
  "task": "ads_plan",
  "status": "ok | partial | blocked",
  "confidence": 0.0,
  "data": {},
  "flags": [{ "level": "high | medium | low", "type": "", "detail": "", "action": "" }],
  "need_human_review": false,
  "sources": [{ "ref": "", "as_of": "" }],
  "assumptions": [],
  "audit": { "snapshot_at": "" }
}
```

- `status`：`ok` 输入齐全 / `partial` 有缺失但结论可用 / `blocked` 关键输入缺失、必须人工先介入。
- 只要出现 `high` 级 flag，`need_human_review` 必须为 `true`。
- `confidence` 口径：有 `high` 不超过 0.7，有 `medium` 不超过 0.85，还有待填位不超过 0.9，上限 0.95。

> 本技能不产出脚本文件，方案以表格与清单形式交付：结构表、出价预算表、阈值表都写成 CSV 或 Excel 交出去，不要只贴在对话里。
> 「层级 / 命名 / 平台 / 站点 / 目标 / 预算 / 出价 / 保本 ROAS / 止损阈值」这套列结构可直接抄 [examples/ad_structure_template.csv](examples/ad_structure_template.csv)。

## 作业习惯

- 先要数据再下结论；能算就不要估，能引用就不要复述。
- 结论固定附「支撑数据 + 判定规则 + 边界/反例」三段，而不是只给一个数。
- `flags` 比结论更重要：写清「我不确定什么、为什么不确认、需要谁确认」。
- 术语保留英文缩写（ROAS、ACOS、TACOS、PO、MOQ、FBA），其余用中文。
